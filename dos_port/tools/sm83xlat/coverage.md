## Branch census — Stage 2's acceptance gate

Every conditional branch, bucketed by how far back the instruction that
wrote the flag it reads is. Measured here with a purely local backward
walk over at most 12 items, with no CFG and no join
points — deliberately, so that the dataflow engine Stage 2 builds is an
**independent** measurement of the same quantity. Two measurements sharing
machinery would agree for reasons unrelated to either being right.

| bucket | branches | share | meaning |
|---|---:|---:|---|
| adjacent | 665 | 72.8% | the immediately preceding instruction writes the flag |
| separated | 98 | 10.7% | a writer is in range, only flag-transparent items between |
| callee-flag-contract | 150 | 16.4% | the nearest candidate is a CALL — the flag comes from a callee's contract, so this is the abi.json question wearing a different hat |
| cross-block | 0 | 0.0% | no straight-line predecessor (an unconditional transfer intervenes, or the window ran out) |
| unmodelled-producer | 0 | 0.0% | the walk hit an item whose flag effect is not modelled — should be zero |
| **total** | **913** | | |

Of the 763 branches with a producer in range, **92** have a label between the
producer and the branch — i.e. another path can enter in between, so the
producer is not guaranteed to be the one that ran. Those are genuine CFG
questions rather than straight-line ones, and the local walk cannot settle
them; they are listed in `tables/probe.json`.

### The plan's quoted proportions do NOT reproduce — read this before using them as Stage 2's gate

The plan states Stage 2's acceptance as reproducing **48.4 / 20.5 / 31.1**
over 920 branches. Decomposed against this run:

- **The branch COUNT reproduces exactly.** 920 = 913 active + 7 that
  sit inside `IF DEF(_DEBUG)` blocks (one `ret nz` per debug hook, in 7
  files) and are therefore not in the build. Nothing is missing.
- **The proportions do not.** Under the definitions above this run reads
  72.8% / 10.7% / 0.0%, with a fourth
  bucket (`callee-flag-contract`) the quoted figures have no slot for.
- A deliberately CRUDER re-bucketing — only a bare SM83 instruction counts
  as a producer, macros and calls skipped as if transparent, no
  unconditional-transfer stop — lands at 47.2% / 26.5% / 26.3%. That is
  the same family as the quoted figures and matches on `adjacent`, so the
  original measurement was probably of this shape — but it is **not**
  reproduced, and this is not a claim that it has been identified.

**Consequence for the plan:** the quoted proportions cannot serve as Stage
2's acceptance gate, because the definition behind them was never recorded
and a gate against an unreproducible number gates nothing. The gate should
be restated as: the Stage 2 dataflow engine reproduces the census in the
table above, whose definitions are written down, on a corpus whose branch
count is independently confirmed at 913 active / 920 total.

The definitional gap is itself the finding. `call` is the crux: treating it
as flag-transparent lets a walk read straight through `call GiveItem` and
credit some earlier `cp` with the CF that `jr nc` actually takes from the
callee. 150 branches read a
flag that way, and each one is an `abi.json` row, not a distance.

## Pointer domain — the first of the two hazards with no textual tell

`ld hl, wCurrentMapScriptFlags` puts a **GB** address in ESI, dereferenced
`[ebp+esi]`. `ld hl, .Text` puts a **HOST** address in ESI, dereferenced
`[esi]`. The two lines are textually identical in shape, so a reviewer
diffing pret against output sees nothing wrong either way — which is why
the classification is reported per site rather than asserted as clean.

| domain at the `ld r16, imm` site | sites |
|---|---:|
| HOST | 755 |
| HOST (local label) | 576 |
| GB | 300 |
| literal (deferred to dataflow) | 10 |
| constant (a count or offset, not a pointer) | 8 |
| **total** | **1649** |

**0 ambiguous, 0 unknown.** Every other site is decided by which
namespace the name lives in, which is a name-level fact and does not need
dataflow. What still does need it: the domain of a pointer that has been
*moved* (`ld d, h` / `ld e, l`) or arrived in a register from a callee.
Those are Stage 2 propagation, not Stage 0 classification, and this table
says nothing about them.
